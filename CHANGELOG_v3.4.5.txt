PrimeTac AUTO v3.4.5 PERSIST LOCK

Главное исправление
- Незавершённый импорт Prom теперь сохраняется в lock-файл.
- После перезапуска процесса lock восстанавливается вместе с import ID, планом групп и fingerprint.
- Пока lock активен, новый импорт не отправляется.
- PREVIOUS_IMPORT_ACTIVE больше не разблокируется автоматически по таймауту.
- Если Prom сообщил SUCCESS, но каталог ещё не совпадает с планом, lock сохраняется и автомат ждёт фактическое подтверждение.

Import ID / Status API
- Добавлено распознавание processed_id / processedId / task_id / uuid в ответе import_file.
- На панели показываются HTTP-код, endpoint и тело последней ошибки проверки статуса.
- Endpoint статуса остаётся /api/v1/products/import/status/{id}.

Защита после Render restart
- Если lock найден, фоновая проверка восстанавливается автоматически.
- Если AUTO_ON_START=true, а lock-файл отсутствует, старт нового импорта после загрузки сервера задерживается минимум на 30 минут (настраивается AUTO_STARTUP_SAFE_DELAY_MIN).
- Старый lock не снимается автоматически. При необходимости ручного аварийного снятия: /auto/unlock?confirm=UNLOCK

Хранилище lock
- AUTO_STATE_PATH задаёт путь файла состояния.
- Если существует /var/data, по умолчанию используется /var/data/primetac-auto-state.json.
- Иначе используется /tmp/primetac-auto-state.json.
- Для сохранения между Render Deploy рекомендуется Render Persistent Disk с AUTO_STATE_PATH=/var/data/primetac-auto-state.json.

Переход со старой v3.4.4
- После любого рестарта кнопка нового импорта блокируется на AUTO_STARTUP_SAFE_DELAY_MIN (по умолчанию 30 мин), если восстановленного lock нет.
- Это защищает именно первый Deploy v3.4.5, потому что v3.4.4 ещё не сохраняла pending import на диск.
